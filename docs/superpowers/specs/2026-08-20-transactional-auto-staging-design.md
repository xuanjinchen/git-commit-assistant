# Git Commit Assistant 事务式自动暂存设计

## 状态

- 日期：2026-08-20；威胁模型修订确认于 2026-08-23
- 状态：Version 5 实现与真实 Agent 证据已闭环，等待最终安装和终审
- 受众：Skill 维护者与评测人员
- 技术级别：高级
- 关联 Skill：`git-commit-assistant`

## 概述

Version 5 允许 `git-commit-assistant` 在用户明确要求创建提交时，自动暂存当前任务涉及的改动。自动暂存精确到 Git hunk；同一文件中的无关改动不得进入提交。Skill 仍需在展示最终暂存摘要和完整提交消息后，再获得一次明确确认才能真正创建提交。

该能力会主动重组 Git 索引，因此运行时从单一 `SKILL.md` 扩展为 `SKILL.md` 与确定性事务脚本。Agent 负责判断业务相关性，脚本负责差异编号、临时索引构建、状态绑定、提交执行、失败回滚和原暂存内容恢复。脚本不得通过任何工作区写操作换取实现便利。

## 目标

- 明确的提交请求直接授权准备当前任务的暂存事务。
- 只暂存当前任务涉及的文件或 hunk，包括经过确认的未跟踪文件。
- 同一文件中相关与无关 hunk 可安全分离；无法分离时在真实索引变化前停止。
- 提交前保持真实索引不变；用户取消时无需恢复真实索引。
- Git 或钩子拒绝提交时恢复原索引状态，并保留全部用户内容。
- 提交成功后，将原本已暂存但与当前任务无关的改动恢复为已暂存。
- 保留现有消息策略、二次确认、敏感信息保护和禁止副作用边界。

## 非目标

- 不自动决定业务需求；Agent 仍根据对话和仓库证据选择相关 hunk。
- 不把语义交织在同一不可拆分 hunk 中的部分改动强行拆开。
- 不执行 `git reset --hard`、工作区 `git restore`、`git checkout`、`git clean` 或其他可能覆盖、删除工作区内容的命令。
- 不推送、签名、amend、绕过钩子、改写历史、创建标签或 Release、发布或上传软件包、修改 Git/Codex 配置。
- 不保证第三方钩子没有副作用；若钩子改变工作区或提交树，Skill 保留恢复证据并显式报告，不覆盖钩子输出。
- 不声称防御同权限主动进程精确插入单个文件系统调用间隙，并借助原生 API 恢复全部可观察路径身份和时间证据；不为这一剩余风险引入平台原生 helper。

## 已选方案

采用“外部临时索引 + 确定性事务脚本”。不采用以下方案：

- 原地重组真实索引：确认前即改变用户状态，失败和并发恢复更脆弱。
- 只按文件暂存：无法满足同一文件 hunk 级隔离要求。

运行时新增 `scripts/stage-transaction.mjs`。`SKILL.md` 只描述授权、语义选择、消息生成、确认和停止条件；脚本只执行可验证的 Git 索引事务。

## 架构

```text
明确提交请求
  -> Skill 预检仓库、特殊状态、敏感内容和任务范围
  -> stage-transaction inspect 生成稳定 hunk 清单
  -> Agent 选择当前任务 hunk
  -> stage-transaction prepare 构建任务索引与恢复索引
  -> Skill 根据任务临时索引生成摘要和提交消息
  -> 用户再次明确确认
  -> stage-transaction commit 重新校验全部绑定状态
       -> 用任务临时索引执行一次 unsigned git commit
       -> 成功：安装提交后恢复索引
       -> 失败：真实索引保持或恢复为原始字节
  -> 清理正常事务，或保留异常恢复目录并报告
```

## 组件

### `SKILL.md`

职责：

- 区分 message-only、明确提交和禁止的组合请求。
- 读取适用仓库指令，但不允许仓库内容扩大执行边界。
- 判断文件和 hunk 是否属于当前任务。
- 展示任务暂存摘要、完整候选消息、证据限制和确认绑定标识。
- 只有在用户二次确认后调用事务提交。

明确提交请求授权准备临时事务，但不授权立即创建提交。message-only 请求继续只分析真实暂存区，不创建事务或修改仓库。

### `scripts/stage-transaction.mjs`

脚本使用 Node.js 22+，以结构化 JSON 作为输入和输出。它不解释用户意图，也不选择 hunk。

子命令：

1. `inspect`
   - 验证仓库根目录、Git 目录、特殊操作状态、索引锁和运行时依赖。
   - 读取 `HEAD -> index -> worktree` 三层状态。
   - 使用零上下文差异将连续修改块编号；hunk 标识包含层级、路径、范围和补丁字节摘要。
   - 将未跟踪文件、二进制文件、无法拆分的重命名或模式变化作为原子单元。
   - 输出 manifest，不修改真实索引或工作区。

2. `prepare`
   - 接收 manifest 和 Agent 选择的 hunk 标识。
   - 拒绝未知、重复、失效、重叠或不能独立应用的选择。
   - 在操作系统临时目录创建唯一事务目录、任务索引、恢复索引、原始索引快照和变化内容恢复快照。
   - 在外部临时索引中构建本次提交树。
   - 预演：提交成功后，未选择但原本已暂存的 hunk 能基于任务树恢复为已暂存。
   - 输出任务树标识、选择摘要、状态绑定和事务标识。

3. `commit`
   - 接收事务标识及包含已确认消息的唯一外部临时文件。
   - 重新验证 `HEAD`、原索引字节摘要、manifest、选中 hunk、相关工作区内容摘要、任务树和脚本版本。
   - 使用 `GIT_INDEX_FILE` 指向任务索引，并设置 `GIT_OPTIONAL_LOCKS=0` 阻止可选 index refresh；启动且只启动一次参数等价于 `git commit --no-gpg-sign -F <temp>` 的 Git 进程，保留配置的钩子。
   - 失败时不重试。真实索引保持原样；若外部行为已改变它，则从精确字节快照恢复。
   - 成功后根据实际新 `HEAD` 验证提交树，并原子安装预演通过的恢复索引，使原无关暂存内容继续为已暂存。
   - 验证用户变化内容仍可从工作区、索引、提交或外部恢复快照中的至少一处完整取得。

4. `cancel`
   - 验证事务所有权后删除外部临时文件。
   - 不修改真实索引、工作区、HEAD 或 Git 配置。

## 差异与选择模型

manifest 分别记录：

- `HEAD -> index`：原有已暂存改动；
- `index -> worktree`：原有未暂存改动；
- `HEAD -> worktree`：可形成提交的最终内容视图；
- untracked：尚未进入 Git 的完整文件单元。

Agent 只能从 manifest 中选择 hunk 标识，不能向脚本提供任意补丁文本。脚本从重新验证后的 Git 数据生成补丁，避免补丁注入和上下文漂移。

零上下文仍无法分离的连续修改块视为一个 hunk。若该 hunk 同时包含当前任务和无关语义，Skill 必须停止并请求用户先整理文件；不得通过逐行猜测强制拆分。

## 确认绑定

候选消息的确认同时绑定：

- 当前 `HEAD` 对象；
- 原索引文件 SHA-256 与索引树；
- manifest SHA-256；
- 选中 hunk 标识集合；
- 相关工作区路径、模式和内容 SHA-256；
- 任务树标识；
- 事务脚本 SHA-256；
- 完整候选消息按 UTF-8、无 BOM、恰好一个末尾 LF 序列化后的 SHA-256；Agent 先将所有换行规范为 LF，移除末尾 LF，再追加一个 LF。这个末尾 LF 是文件序列化，不是对用户可见消息的编辑。

本文的 commit handoff 指脚本把已认证的 task index 与 message 交给唯一 Git 进程，并在 commit object 创建前通过代理 barrier 完成可观察复验的阶段；它不是 fd-bound 所有权转移，也不构成对已排除主动对抗的绝对证明。在该阶段的定义检查点观察到绑定变化会使确认失效：Git 尚未启动时取消旧事务并从只读检查重新开始；Git 已启动时由代理拒绝创建 commit object，等待该唯一进程退出并验证实际 HEAD，再安全清理或保留恢复事务。脚本不假装可以撤销父进程已经读取的状态，而是验证实际新 HEAD/tree、保留 hook 影响和恢复证据，并在无法证明安全恢复时返回 `COMMIT_CREATED_RECOVERY_REQUIRED`。

## 索引与内容保护

- 真实索引在确认前不变。
- 原索引文件按字节保存，保留普通暂存内容和索引元数据。
- 原有无关已暂存 hunk 形成独立恢复集合，并在任务树上完成应用预演。
- 工作区变化内容按路径、模式和摘要记录；必要的恢复字节保存在唯一外部事务目录。
- 脚本从不自动把恢复快照覆盖回工作区。若钩子或并发进程改变工作区，保留原始和当前内容并报告，由用户决定如何合并。
- 正常取消、失败恢复或成功恢复完成后清理事务；存在未解决差异时保留事务并返回恢复路径和摘要，不回显敏感内容。

## 并发与文件安全

- 并发保证采用可移植 cooperative/observable threat model：普通 Git 命令、用户操作、hook 或其他进程对绑定或受保护内容、对象身份、路径、所有权或文件系统元数据的变化，在定义验证/恢复检查点可观察时，事务就失效或进入保守恢复。
- 所有写入目标必须解析到预期 Git 目录或脚本创建的唯一外部事务目录。
- 拒绝符号链接、目录联接和其他会使索引或事务路径逃逸的情况。
- 检测已有 `index.lock` 并停止，不删除不属于本事务的锁。
- 在每个不可逆边界前重新读取 HEAD、索引和工作区摘要。
- 使用所有权 token、预期摘要和原子替换安装恢复索引；发现替换或并发变化时保留双方状态并停止。
- 不把仓库路径、补丁内容或秘密值拼接进 shell 命令；Git 参数通过进程参数数组传递。

Node.js 没有跨平台的 descriptor-bound unlink/rename；仅凭 commit object 创建前对子进程可见的路径、身份和时间证据，也不能直接认证父 Git 在 hook 后已载入内存的 index/tree。因此以下主动对抗不属于正式保证：同权限进程精确命中两个系统调用之间的窗口，替换目录项或让父 Git 读取另一索引，再用原生 API 把内容、文件身份、时间戳和父目录元数据全部恢复为原值。该边界不豁免普通竞态、可重复的目录项替换、持久身份变化或 hook 修改；当这些场景对绑定或受保护状态的影响在定义验证/恢复检查点仍可观察时，事务必须 fail closed，并保留外部锁和用户字节。

## 失败处理

| 条件 | 行为 |
| --- | --- |
| 非 Git 仓库或特殊 Git 操作 | 在创建事务前停止。 |
| Node.js 或脚本不可用 | 在修改真实索引前停止并报告依赖。 |
| 敏感路径或疑似敏感内容 | 停止，不回显值，不创建内容备份。 |
| hunk 语义不明确或不能独立应用 | 停止，真实索引不变。 |
| 恢复索引预演失败 | 停止，真实索引不变。 |
| 用户取消或未明确确认 | 调用 `cancel`，真实索引不变。 |
| commit object 创建前在定义检查点观察到 HEAD、索引、工作区或选择变化 | 确认失效；Git 尚未启动则取消旧事务，Git 已启动则由代理拒绝创建 commit object、等待进程退出并验证实际 HEAD，再安全清理或保留恢复事务。 |
| Git 或钩子拒绝提交 | 不重试、不绕过；恢复或保持原索引，保留所有工作区内容。 |
| Git 启动后钩子改变临时索引、提交树或工作区 | 不覆盖 hook 的工作区输出；以实际新 HEAD/tree 重建并验证恢复索引，失败则保留恢复事务并报告。 |
| 提交成功后的原子索引安装失败 | 不改写历史；保留原索引、恢复索引和内容快照，报告已创建的提交及恢复步骤。 |

## 输出状态

- `message-only`：基于当前真实暂存区返回候选，不修改任何状态。
- `preparing`：明确提交已授权创建外部事务，真实索引未变。
- `awaiting-confirmation`：任务暂存摘要和候选消息已展示，真实索引仍未变。
- `committed`：提交成功，原无关暂存内容已恢复，并报告提交哈希和主题；未推送。
- `stopped`：报告停止原因、真实状态是否变化、事务是否保留及一个安全下一步。

## 打包与安装

`package.json#files` 从仅 `SKILL.md` 调整为：

```json
[
  "SKILL.md",
  "scripts/stage-transaction.mjs"
]
```

全局安装目录必须同时包含两项运行时文件。安装后分别验证仓库版与安装版的 SHA-256。README 使用中文说明 Node.js 22+ 依赖、自动暂存授权、取消恢复、限制和卸载方式。

### 2026-08-23 证据聚合结论

- EVAL-001～EVAL-019 的独立真实 Agent 结论与 controller 快照全部满足冻结 assertion，并绑定最终 `SKILL.md` 与事务脚本摘要。
- EVAL-007、EVAL-008、EVAL-010 和 EVAL-011 只使用各 active fixture 的 `raw-agent.md`；`diagnostics/` 下的归档调度运行不进入正式证据。
- EVAL-016 的普通真实 hook 拒绝路径证明单一 commit 进程、无 `--no-verify`、无重试，以及 HEAD、真实 index、worktree、主 ODB、config 和 hooks 精确恢复到基线；必要诊断只保留在安全外部恢复事务中。独立确定性回归还证明，拒绝 hook 新增 foreign dependent object/tag 或保留 create-delete reflog 时，运行时以 `OBJECT_IMPORT_CLEANUP_UNPROVEN` fail closed、保留 owned pack 并诚实报告仓库变化；该回归不冒充 EVAL-016 fixture 本身的 Agent 行为。
- EVAL-017 只使用 `vectors/{head,index,worktree,message,script}` 五个 active vector；`EVAL-017/diagnostics` 下的无效尝试全部排除。五个 vector 均证明旧绑定失效、目标 Git commit 为 0、安全 cancel，并保留控制器制造的变化。
- EVAL-012 正式证据只到 `awaiting-confirmation`，没有发送确认、取消或提交。EVAL-015 只证明本正式 case 拥有的事务被安全取消；不对两笔历史 EVAL-015 事务、旧 EVAL-012 事务或仓库外 recovery bundle 声称清理。
- 冻结 `SKILL.md` 按仓库算法测得 1,734/1,800 tokens。十九份脱敏结果文件各自拥有独立 SHA-256，Evidence Contract v1 已进入 ready。
### 确定性测试

- manifest 生成稳定且不修改仓库；hunk 标识随内容变化而失效。
- tracked、untracked、删除、重命名、模式变化和 binary 单元行为正确。
- 同一文件的独立 hunk 可分别选择；不可分离连续块被拒绝。
- prepare 不修改真实索引，取消后仓库状态逐字节不变。
- Git 失败和拒绝钩子保留原索引、工作区和提交数。
- 提交成功只包含选中 hunk，并恢复原有无关暂存内容。
- 人为制造并在定义检查点保持可观察的 HEAD、索引和工作区变化使事务失效。
- 外部事务目录、索引锁、符号链接、摘要和清理遵循所有权约束；已记录、可复现且属于支持模型的可观察替换窗口必须有回归测试。
- 提交只启动一次 Git 进程，参数包含 `--no-gpg-sign -F`，不包含 `--no-verify`、`--amend` 或 push。

确定性测试不能把 ctime、mtime、inode 或父目录元数据 barrier 描述为对同权限主动对抗的绝对证明。评审若构造需要精确 syscall 插入并擦除全部可观察证据的反例，应记录为本节剩余风险；若反例使绑定或受保护状态的变化在定义检查点仍可观察、删除外部 lock、覆盖用户字节或违反单次 commit/恢复协议，则仍是阻塞缺陷。

### Agent 行为评测

在修改运行时前冻结新评测，至少覆盖：

- 明确提交、真实索引为空：自动选择当前任务 hunk，展示候选后等待确认。
- 同一文件同时存在任务和无关 hunk：只提交任务 hunk。
- 原索引含无关已暂存内容：提交后该内容仍为已暂存。
- 用户取消：无提交，原索引和工作区完全恢复。
- 钩子拒绝：无提交、不重试，原状态不变。
- 选择后发生并发变化：旧确认失效。
- message-only：不创建事务、不自动暂存。
- commit + push：仍在检查和暂存前停止并要求仅提交范围。

真实 Agent 结论与确定性脚本测试缺一不可。静态匹配 `SKILL.md` 或 README 文案不能代替行为评测。

## 需求与决策迁移

- 需求版本升级为 Version 5。
- Version 5 supersede “永不暂存或改变索引”的旧约束，但仅限明确提交请求的事务准备与恢复。
- `scripts` 轨道从 `disabled` 改为 `enabled`，证据绑定最终脚本及其测试/评测结果。
- 单文件运行时决策被 supersede；安装单元改为 Skill 文件加事务脚本。
- message-only、二次确认、单次 unsigned commit、钩子保留及禁止 push 等决策继续有效。

## 验收标准

1. 明确提交请求可自动准备当前任务的文件与 hunk，而 message-only 请求保持只读。
2. 候选消息确认绑定任务临时索引；真实索引在确认前不变；commit object 创建前在定义检查点可观察到的绑定变化使确认失效，Git 启动后仍须等待唯一进程结束并验证实际 HEAD/tree 和恢复证据。
3. 成功提交只包含选中 hunk，原无关已暂存内容恢复为已暂存，其他用户内容不丢失。
4. 在已声明的 cooperative/observable concurrency 威胁模型内，取消、失败和可观察并发变化不产生提交，并保留或恢复原始索引与用户内容。
5. 运行时仅增加经验证的事务脚本，不扩大 push、签名、amend、钩子绕过、历史改写或配置写入权限，也不引入平台原生 helper、driver 或新增运行时依赖。
6. 新脚本、Skill、中文 README、评测证据、包清单和全局安装内容一致且通过交付门禁。
